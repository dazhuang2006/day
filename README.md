# 《星莓的一天》· 今天好像有点不一样

为一（位）特别的人准备的《小马宝莉》风格生日小游戏。

玩家扮演**星莓**，陪她度过看似普通的一天——收集花朵、寻找材料、制作甜点、布置小屋。
直到最后才明白：这一整天的准备，原来都是为了给玩家自己准备惊喜。

> 前 80% 剧情刻意不出现“生日 / 生日礼物 / 生日蛋糕 / 生日派对”等关键词，
> 只用“今天 / 她 / 秘密 / 特别的准备”等模糊表达。谜底在终章才揭晓。

---

## 运行方式

```bash
npm install
npm run dev
```

浏览器会自动打开 `http://localhost:5173/`（若未自动打开，手动访问即可）。

> 依赖 Node 18+。项目完全自包含：所有角色与道具贴图由代码动态绘制，**无需任何外部美术资源**。

## 操作

手机和电脑都能玩，**全程只用点击/触摸也能通关**。

**手机 / 平板（触摸）**

| 操作 | 作用 |
| --- | --- |
| 点一下地面 | 星莓走过去（点得不太准也没关系：附近有东西会自动走到它跟前） |
| 走到东西旁边 | **自动互动**，不用按任何键 |
| 点屏幕任意处 | 推进对话、继续读信 |
| 点标题按钮 | 新游戏 / 继续 / 设置 |

> **每个能互动的地方都有一圈会呼吸的提示光圈**，走过去光圈会变亮、底部提示也会切换成
> "走到发光的位置就会自动互动"，所以不会出现"走到这里怎么没反应"。
> 竖屏时会提示"把手机横过来"，转成横屏提示自动消失（这个游戏是 16:9 宽屏画面）。

**电脑（键盘 + 鼠标都可以）**

| 按键 | 作用 |
| --- | --- |
| `W A S D` 或 方向键 | 移动星莓（会朝四个方向转身） |
| 鼠标点击地面 | 同手机：点哪走哪 + 自动互动 |
| `E` 或 `空格` | 与花、盒子、角色、布置点交互（自动就近判定） |
| `空格` / `回车` / `点击` | 推进对话 / 打字机快进 |
| 长按 `Ctrl` | 对话加速 |
| `Esc` | 跳过整段对话 |
| `M` | 静音 / 取消静音（随时可用） |

标题界面的「设置 / 音量」可以调音量与文字速度，设置单独存档，清进度不会丢。

## 存档

- 进度会自动存进浏览器 `localStorage`，关掉页面再打开就能看到「继续」按钮。
- 标题界面提供：**新的一天**（重开）、**继续**（回到当前章节开头）、**跳过序章**、**设置**。
- 继续时会跳过已经看过的开场白，并恢复已收集的花 / 材料 / 布置进度。
- 想彻底重来：标题界面点「新的一天」即可（会清掉旧存档）。

## 章节流程

| 章节 | 场景 | 内容 |
| --- | --- | --- |
| 序章 | 星莓的房间 | 清晨醒来，把一个小盒子藏起来（紫悦叮嘱过：先藏好） |
| 第一章 | 梦幻花园 | 先找**柔柔**问清三朵花的用意 → 采集粉 / 紫 / 白三朵花 |
| 第二章 | 小屋 | **紫悦**来核对今天的时间表 → 找齐包装材料，珍奇帮忙包礼物 |
| 第三章 | 苹果园 | **苹果嘉儿**交代五样材料（**碧琪**差点说漏嘴）→ 收材料 → 装饰甜点 |
| 第四章 | 傍晚小屋 | 和六位朋友一一打招呼，她们各自带来一份布置物 → 亲手布置小屋 |
| 第五章 | 夜晚 | **云宝**报信“她来了” → 敲门 → 开门 → 灯光亮起 → 所有人出现 |
| 终章 | 小屋 | 生日信、结尾语、自由互动与隐藏彩蛋 |

> **每章都要先和任务角色对话，才会解锁本章的收集与交互**：
> 没打招呼就去采花 / 捡材料 / 布置，星莓只会提示你“先去找谁”。
> 第四章每位朋友负责带来一件东西（紫悦带灯串与桌布、云宝带星星装饰、
> 碧琪端甜点、柔柔养花、苹果嘉儿摆礼物、珍奇挑彩带），收到后才能布置。

通关后进入**自由互动模式**：可点击每位角色听彩蛋台词，点击小屋里的星星 / 花触发“回忆碎片”。

## 可定制点（都在 `src/data/` 下）

- **`birthdayLetter.ts`** —— 终章的生日信全文，独立存放，改这里即可换信的内容。
- **`dialogue.ts`** —— 各章节对话脚本，按场景数组组织，方便整体改写剧情。
- **`memories.ts`** —— 自由模式里的回忆碎片。
- **`music.ts`** —— 合成音乐配方（和弦进行 / 节奏 / 音色），没放 mp3 时用它。
- **`config.ts`** —— 花朵 / 材料 / 布置任务 / 装饰选项等可配置项，以及星莓的外观配色。

## 音乐

- 目录：`assets/audio/`，按 `morning/garden/orchard/evening/surprise/birthday.mp3` 命名即可自动播放。
- 文件缺失**不会报错**：程序会用 WebAudio 合成的音乐兜底。
  合成配方在 `src/data/music.ts`（明亮的大调和弦进行 + 柔和垫音 + 轻快琶音），
  想换情绪直接改那里的和弦与节奏即可。
- 音乐有"厚度"分层：收集 / 布置越多，层次越满（垫音 → 加琶音 → 加低音层），
  由各场景调用 `audioManager.setIntensity()` 控制。
- 浏览器自动播放策略：首次点击或按键后音乐开始。

## 合成人声

终章"生日快乐"是**七位角色各自的声线**（依次说一遍，最后所有人合唱），
同样没有音频素材，全部由 WebAudio 现场合成：

- 配方在 **`src/data/voice.ts`**：每位角色有自己的基频、音色（锯齿 / 方波 / 三角 / 正弦）、
  颤音、语速与气息量。"生日快乐"的四个音节（ㄕㄥ ㄖˋ ㄎㄨㄞˋ ㄌㄜˋ）编成一小段上行旋律。
- 每个音节 = 带颤音的声带 + 三个共振峰带通滤波器（按元音 a/e/i/o/u 取中心频率）
  + 音量包络，所以听起来像"在唱"而不是单纯蜂鸣。
- 想调某位角色的声音，改 `VOICES` 里的数值即可；
  **如果你录到了真实配音**，把 mp3 放进 `assets/audio/`，然后把对应行改成播放音频就行
  （`audioManager.sayAs()` 是唯一的调用入口，改一处即可）。

## 代码结构

```
src/
├── main.ts                 # Phaser 入口
├── config.ts               # 全局配置、章节进度与进度状态
├── persistence.ts          # localStorage 存档读写
├── textures.ts             # 程序化贴图（角色四朝向 / 道具 / 粒子）
├── audio.ts                # 音频管理（mp3 兜底 + 自动播放策略处理）
├── player.ts               # 星莓移动、朝向与交互
├── sceneUtils.ts           # 淡入淡出 / 提示 / toast / 交互就近仲裁
├── scenes/                 # 标题与各章节场景 + 通用对话组件 dialogue.ts
├── characters/             # 星莓与六位小马角色
├── objects/                # Collectible / Gift / Decoration
└── data/                   # 剧情数据（对话 / 回忆 / 生日信）
```

## 部署 / 分享给别人玩

游戏是纯静态的（无后端、无数据库），所以把它挂到公网只需要一个隧道或一个静态托管。

### 方式一：ngrok 隧道（最快，适合临时分享）

```bash
npm run share     # 构建 + vite preview（监听 4173，已允许隧道域名）
npm run tunnel    # 另开一个终端：ngrok http 4173
```

三个容易踩的坑，本项目已经处理好前两个：

1. **Vite 的 Host 校验**：Vite 6 默认拒绝非本机域名，会返回 `Blocked request`。
   [vite.config.ts](vite.config.ts) 里已设 `allowedHosts`（同时 `host: true`、`open: false`）。
2. **用生产构建而不是 dev server**：`npm run share` 走的是 `vite preview`，
   页面更小更稳，也不会有 HMR/WebSocket 的额外问题。
3. **ngrok 免费版的警告页（仍然存在，无法绕过）**：
   第一次用浏览器打开会看到一个 `ERR_NGROK_6024` 提示页，需要点一下 **Visit Site**。
   点过之后会写 cookie，**之后每次访问都直接进游戏**。
   - 让 ngrok 带上 `ngrok-skip-browser-warning` 头是**没用的**：警告页是在 ngrok 那一层插的，
     浏览器请求根本没到你的服务；去掉警告页需要 ngrok 付费版。
   - 所以分享时最好附一句："打开后点一下中间的 Visit Site"。

### 方式二：静态托管（最省事，适合真的当礼物送出去）

因为 `base: './'` 用的是相对路径，`dist/` 可以原样丢到任何静态托管上：
Netlify Drop（拖文件夹即可）、Cloudflare Pages、Vercel、GitHub Pages、对象存储 + CDN 都行。
没有警告页、链接稳定、也不用一直开着你的电脑。

### 分享时值得知道的两点

- **存档是跟域名走的**（`localStorage`）：换域名/换隧道地址，对方的进度就是一份新的。
  要长期保留进度就固定域名（方式二）。
- **首次点击后才有声音**：浏览器自动播放策略要求一次用户手势，
  标题界面点"新的一天"之后就正常了（音频上下文会变成 `running`）。
